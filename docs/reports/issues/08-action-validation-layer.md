# Issue Report: Action Validation Layer

## Summary
A validation layer has been implemented in `orchestrator/validator.py` and integrated into the `Orchestrator` class. This layer ensures that any command generated by the LLM is checked against the tool manifest for existence and parameter accuracy before execution.

## Files Changed
- `orchestrator/validator.py`: New file containing the `validate_action` function, which performs checks for action existence, required parameters, and unexpected parameters.
- `orchestrator/brain.py`: Updated the `process_command` method to invoke the validation logic immediately after JSON parsing.

## Validation Performed
- **Existence Check**: Verified that actions not present in the `TOOL_MANIFEST` are caught and returned as errors.
- **Required Parameters**: Confirmed that missing required parameters (e.g., `name` for `create_project`) trigger validation failures.
- **Unexpected Parameters**: Ensured that any "hallucinated" parameters from the LLM are detected and blocked.
- **Functional Integrity**: Confirmed through a test suite (`verify_validator.py`) that valid commands still pass through correctly and execute as expected.

## Known Limitations
- The current validation is structural (parameter names/existence). It does not yet perform deep type checking (e.g., ensuring a string is passed where a string is expected) or complex business logic validation.

## Follow-up Recommendations
- Extend the validator to perform type enforcement once the basic orchestrator is stable.
- Add error recovery logic to the orchestrator to potentially "re-prompt" the LLM if validation fails.
